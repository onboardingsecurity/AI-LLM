# today-info-board — 작업 마무리 체크리스트

커밋을 만들거나 기능 구현 작업을 마무리할 때마다, 다음 항목을 순서대로 실제로 확인하고 근거와 함께 보고한다. 항목을 건너뛰거나 결과를 숨기지 않는다.

**보고 형식:** 각 점검 결과는 "통과" 또는 "실패" 둘 중 하나로만 적는다. 통과가 아닌 것(미충족, 확인 못 함, 해당 없음 등)은 전부 "실패"로 적고, 왜 실패인지 이유를 바로 옆에 적는다("확인 못 함"이면 무엇 때문에 확인할 수 없었는지가 이유). 단, 사용자 담당 항목(아래 1번 참고)은 Claude가 판정하지 않는 별도 범위 표시이지 통과/실패 결과가 아니다.

## 1. 통과 기준(T04-Cxx) 점검

`assets/studio-task-assets/t04-real-information-board/criterion-registry.json`이 정본이다. 이번 변경이 건드릴 수 있는 조건을 골라 실제로 돌려보고, 조건 ID별로 통과/실패를 표로 보고한다(실패면 이유 포함).

- 사용자 담당(공유/제출 계열: C01, C02, C29~C35)은 판정하지 않고 "사용자 담당"으로만 표시한다 — 통과/실패 대상이 아니다.
- 자동 점검 스크립트가 있으면 그걸 돌리고, 없으면 임시 폴더에서 확인용 스크립트를 돌린 뒤 조용히 정리한다.

## 2. 출처/근거 기록 확인

새 자산(이미지, 데이터, 픽스처 등)을 추가하거나 교체했으면, 출처가 어딘가에 기록되어 있는지 확인한다 (`docs/T04-evidence.md` 등). 기록이 있으면 통과, 없으면 실패(이유: 어떤 자산의 출처가 어디에도 기록이 안 되어 있는지) — 임의로 지어내지 않는다.

## 3. 프로젝트 폴더 밖 시스템 변경 확인

이번 작업으로 `today-info-board/` 폴더 밖의 시스템 설정(launchd, 전역 설정 파일, 다른 프로젝트 등)을 변경한 것이 있는지 확인한다. 없으면 통과, 있으면 실패(이유: 무엇을 왜 바꿨는지). 폴더 밖 변경은 사전에 확인받지 않았다면 하지 않는다.

## 4. 개인정보·비밀 키 노출 확인

이번에 만들거나 수정한 파일에 개인정보, API 키, 비밀번호, 토큰 등 보안적으로 위험한 값이 포함되었는지 확인한다. 없으면 통과, 있으면 실패(이유: 어느 파일에 무엇이 있었는지).

## 5. 요구사항 명세 전체 점검

말로 전달받은 요구사항과 `criterion-registry.json` 명세를 함께 놓고, 이번 변경이 명세를 어기거나 미흡하게 구현한 부분이 없는지 전체적으로 점검한다. 개별 조건 통과 여부(1번)와는 별개로, 명세 전반과 실제 구현이 어긋나는 지점이 있는지 보는 단계다. 어긋남이 없으면 통과, 있으면 실패(이유: 어떤 명세와 무엇이 어긋나는지).

## 6. 변경 파일·전체 파일 보안 점검

이번에 생성·수정·삭제한 파일과 프로젝트 전체 파일을 대상으로, 시스템에 해를 끼치거나 보안적으로 위험할 수 있는 코드·설정(예: 임의 코드 실행, 위험한 권한 요청, 알 수 없는 외부 요청 등)이 있는지 확인한다. 없으면 통과, 있으면 실패(이유: 어느 파일의 어떤 코드·설정인지).

## 7. 보고 및 허가

1~6번을 전부 확인한 뒤에만 사용자에게 결과를 보고하고, 다음 단계(특히 커밋·push·배포)로 넘어가기 전에 허가를 받는다. 커밋·push·배포는 사용자가 직접 하며, Claude가 먼저 하거나 권하지 않는다.
