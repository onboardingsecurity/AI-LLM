# T05 요구사항 명세서

## 목적

긴 작업에서 중요한 것은 한 AI의 기억이 아니라 저장소와 인수인계 품질이다.
대화 전문 없이도 같은 검사를 이어서 통과시키는 운영 능력을 확인한다.

## 과제와 작업자

| 항목 | 값 |
|---|---|
| 과제 3 | 짤·카드 스튜디오 |
| 과제 4 | 오늘의 진짜 정보판 (데이터가 안 올 때) |
| 이번에 고를 기능 | (작업 시작 전 기록: 과제 3 또는 4에서 기능 한 개) |
| AI A | Claude Code |
| AI B | ChatGPT |

비교표(C28 판정 구간)에서는 A/B로만 표기한다. 실제 이름 매핑은 `docs/handoff/name-mapping.md`에 따로 둔다.

## 흐름

1. 검사 10개와 공통 상한(시간 1개, 요청·호출 수 1개)을 고정한다.
2. AI A 시작 → AI A 종료·인수인계 → AI B 시작 → AI B 종료 순서로 기록한다.
3. 이름을 가린 표로 비교하고, 다음 작업의 도구 선택 기준을 정한다.

## 정의

- **버전 ID**: git 커밋 해시. 인수인계 문서의 버전 ID는 "문서를 쓰기 직전 커밋"을 가리킨다. 문서를 고치는 커밋은 따로 둔다.
- **오류 수**: 고정 검사 10개를 한 번 전체 실행한 것을 1회차로 보고, 그중 하나 이상 FAIL이 나온 회차의 수. 일부 검사만 따로 돌린 것은 회차로 세지 않는다.
- **재작업량**: 제출 뒤 로컬 채점기가 A·B 각각의 시작·종료 고정 소스 버전 쌍으로 계산한 추가·삭제 줄 수. 생성 파일과 lockfile은 제외한다. 수기로 입력하지 않는다.
- **검사 삭제·완화·변경**: 시작 때 저장한 검사 ID·입력·기대값의 해시와 종료 때 해시를 비교해 판정한다. 하나라도 달라지면 위반이다.

C22, C32~C36, C40~C49는 아직 전달받지 않았다. 번호를 임의로 채우지 않고, 전달받으면 이 표에 그대로 추가한다.

## 막히는 지점과 확인 순서

| 상황 | 확인 순서 |
|---|---|
| 검사가 구현 방법만 확인한다 | 사용자 입력으로 바꾸기 → 관찰 가능한 기대값 쓰기 → 경계값 포함 |
| 멈출 때 무엇을 저장할지 모른다 | 현재 버전 ID → 실행 명령 → 첫 실패 검사 → 다음 행동 |
| 문서는 맞아 보이지만 새 환경에서 안 된다 | 필요 버전 → 설치 명령 → 환경값 예시 → 작업 폴더 |
| AI B가 앞 대화를 요구한다 | 문서의 현재 상태 보완 → 첫 실패 검사 추가 → 대화 전문은 제공하지 않음 |
| 느낌 말고 비교할 값이 없다 | 검사 통과 수 → 소요 시간 → 호출 수 → A·B 각각의 시작·종료 고정 소스 버전 쌍 |

## 남길 것

- 초기 검사 10개와 공통 사용 상한, AI A와 B에 쓴 같은 최초 요청과 검사, AI A 시작 시각과 시작 소스
- AI A가 멈춘 소스와 검사 결과, 실제 사용량, 인수인계 문서
- 인수인계 문서와 새 폴더 재현 결과, A가 남긴 인수인계와 B가 받은 내용의 동일성 증거
- AI B에 제공한 저장소와 인수인계 문서, AI B 최종 검사·사용량, A 시작 → A 인계 → B 시작 → B 완료 순서
- 가린 비교표(시간·요청/호출·오류·통과 수), 전체 작업 기록, 다음 작업의 도구 선택 기준
