### 3.2 앱 구현(`app/`)

정적 웹앱입니다. 빌드가 없고, 외부 요청·저장·AI 호출이 없습니다. `index.html`을 더블클릭하면 열립니다(`file://`에서도 동작).

| 파일 | 역할 |
|---|---|
| `index.html`, `style.css` | 화면과 픽셀 스타일 |
| `script.js` | 화면 동작: 알림 창(`notify`), 클릭 효과, 직업 타일, 호칭 버튼, 가격 −/+ 버튼, 비교 결과 |
| `logic.js` | `App.logic`: `parsePrice`, `findTitle`, `position`, `kindOf`, `compare`, `single`, `isOutside`, `consumerView`, `paperExtras` |
| `data.js` | `App.data`: 표 1 호칭 5개(원장 10곳, 디자이너 9곳, 아티스트 7곳, 네일리스트 6곳, 선생님 5곳), 기준 5,000원, 직업 세 개, 입력 범위 1,000~1,000,000원 |
| `messages.js` | `App.messages`: 헤드라인, 상태마다 공감 한 줄 6개(`feeling`), 이유·근거·한계 문구, 소비자 입장 문장 틀 |
| `fonts/`, `assets/`, `CREDITS.md` | 주아체(SIL OFL), 배경·캐릭터·커서(사용자가 AI로 만든 이미지를 다른 브랜치에서 복사, 해시 동일), 직접 그린 아이콘, 출처 표기 |
| `vercel.json` | 콘텐츠 보안 정책 `default-src 'none'; script-src 'self'; ...`, `nosniff`, `no-referrer` |
| `README.md` | 실행 방법(더블클릭), 환경 변수 없음, 논문 결과 쓰는 방법, 데이터 설명 |

스크립트 로드 순서는 `data.js`, `messages.js`, `logic.js`, `script.js`이고 모두 `globalThis.App` 하나를 공유합니다.

**판단 규칙**
- 두 가게 가격 차이를 5,000원과 비교해 A(미만, 차이 작음), B(같음, 경계), C(초과, 차이 큼)로 나눕니다.
- 각 가게 가격은 그 호칭의 논문 범위에서 `belowMin`, `low`, `mid`, `high`, `aboveMax` 중 어디인지 보여 줍니다.
- 결과 화면의 공감 한 줄은 `messages.feeling`에 상태마다 하나씩(두 가게 A·B·C, 한 곳 낮은 쪽·가운데·높은 쪽)만 있습니다. 같은 입력이면 같은 문장입니다.
- 결과 화면에는 이유(가격 차이와 기준 비교, 호칭별 곳수·중앙값·가운데 절반·최저·최고, 논문 결론)가 항상 함께 보입니다. BRB-C04의 근거라서 빼면 안 됩니다.
- 공감 한 줄과 소비자 입장 문장은 인과 단정("호칭 때문에 비싸다")과 가라·말라는 권유를 쓰지 않습니다. 테스트가 막습니다.
- 논문의 결론은 "뚜렷한 증거 없음"이고 경계값 판정만 "차이 있음"이었다는 점을 앱도 같이 보여 줍니다.

**픽셀 스타일**
- 토큰: `--pixel-ink: #3b2a1e`, `--px2`·`--px3` 상자 그림자 테두리, `--drop`, `--bevel`, 강조색 #c2410c, 연한 바탕 #ffe9d2.
- 알림은 브라우저 `alert` 대신 `<dialog>`(체크무늬 막대 포함), 움직임은 `steps()`, 버튼은 눌리면 `translateY(3px)`.
- 클릭 효과: 결과 A는 하트, B는 물음표, C는 느낌표가 올라가고 캐릭터를 눌러도 하트가 올라갑니다(`FX_BY_KIND`).
- 직업 아이콘은 `tools/make_pixel_icons.py`가 글자 지도로 그려 PNG로 씁니다(표준 라이브러리만 사용). 준비 중인 직업은 같은 그림의 회색판(`-off`)과 자물쇠가 붙습니다. 아이콘을 바꾸려면 이 스크립트의 글자 지도를 고치고 `python3 tools/make_pixel_icons.py`를 다시 실행합니다.
- 화면 글자는 주아체입니다. 비트맵 픽셀 한글 글꼴은 쓰지 않았습니다(사용자에게 알렸고 별 반응 없음).

**직업 타일 현재 구성**: 네일(손톱 그림, 열림), 요리사 vs 쉐프(쉐프 모자, 잠김), 개발자 vs 엔지니어(노트북 `</>`, 잠김). 직업 이름은 사용자가 직접 정해 준 것입니다.

## 6. 사용자의 작업 규칙(어기지 마세요)

- **파일 수정·생성·삭제는 먼저 묻는다.** 사용자가 그 턴에서 명시적으로 시킨 것은 해도 됩니다.
- **커밋·푸시·배포는 사용자가 요청할 때만 한다.** 하지도 권하지도 않습니다. 배포는 사용자가 직접 하고 제출 직전에 한 번만 합니다. 로컬에서 먼저 시험합니다.
- **커밋을 요청받으면**: 먼저 보안 점검(올라갈 파일 목록, 금지 파일명, 키·개인정보·경로 패턴, 큰 파일). 문제가 없을 때만 진행. `git config`에 개인 주소가 설정돼 있으므로 반드시 noreply 주소로 덮어씁니다: `git -c user.name=onboardingsecurity -c user.email=<noreply 주소> commit`. noreply 주소는 `git log --format=%ae`에서 최근 커밋의 작성자 주소를 그대로 씁니다. 문서에는 이메일 주소를 적지 않습니다.
  - 파일은 하나씩 `git add`하고(zsh에서는 배열 `G=(git -c ...)`로 명령을 만든 뒤 `$G commit`), 논리 단위로 나눕니다.
  - 메시지 형식은 `type: 요약`이고 문서 커밋에는 `(✅ n / ⏳ n / ➖ n / ❌ n)`을 붙입니다. 끝에 그 세션의 시스템 안내가 알려 주는 `Co-Authored-By: Claude ...` 줄을 붙입니다(모델 이름과 주소는 세션마다 다를 수 있으니 안내대로). 푸시 전에 상태를 확인합니다.
- **한 번에 하나씩 짧게 안내한다.** 정보를 한꺼번에 쏟지 않습니다.
- **지어내지 않는다.** 사용자가 주지 않은 사실(삶의 사실, 동료, C16~C21 같은 기준)은 만들지 말고 물어봅니다. 외부 자료를 못 찾으면 바로 지어내지 말고 재확인합니다.
- **프로젝트 폴더 밖은 건드리지 않는다.** 시스템 설정, launchd, 전역 설치는 먼저 확인받습니다. 확인용 임시 파일은 세션의 scratchpad에만 둡니다.
- **사용자가 직접 고친 부분이 요구사항에 어긋나면 알려 줍니다.**
- 서비스 이름은 사용자가 **"대구! 갈래? 말래?"**로 정했고, 대구 범위는 이 이름으로 알립니다. 이름을 바꾸자는 제안은 하지 마세요(물어보면 답합니다).

## 7. 도구 사용 메모(겪은 문제)

- 한국어 문장이 많은 파일은 `Edit`이 문장 차이로 실패하기 쉽습니다. 여러 곳을 고칠 때는 Python으로 `assert old in s`를 건 뒤 바꾸는 방법이 안전했습니다.
- zsh에서 `$B:css/...`는 `:css`가 수정자로 해석됩니다. `${B}:css/...`로 씁니다. `grep --exclude=*.png`는 따옴표 없이 쓰면 zsh가 확장하므로 `--exclude='*.png'`로 씁니다.
- 테스트는 Node `vm` 안에서 `app/*.js`를 실행합니다. 다른 realm이라 배열 비교에는 `Array.from(...)`을 씁니다.
- 헤드리스 Chrome으로 화면을 찍을 때는 입장 애니메이션 때문에 빈 화면이 나오니 `--virtual-time-budget=3000` 같은 옵션을 줍니다. 출력에 나오는 `CVDisplayLinkCreateWithCGDisplay failed`와 `task_policy_set` 오류는 맥 환경 메시지이고 앱 오류가 아닙니다. 프로필은 `--user-data-dir`로 scratchpad에 따로 둡니다.
- 클릭 흐름 확인용 `drive.js`는 저장소에 없습니다(세션 scratchpad에만 있었음). 필요하면 임시 복사본의 `index.html`에 `<script src="drive.js">`를 붙이고, 주소 끝 `#a`, `#b`, `#c`, `#bad`, `#off`를 읽어 `#job-list button`을 누르고, `#picker-N [data-value="호칭"]`을 누르고, `#price-N`에 값을 넣은 뒤 `#compare-form`의 `requestSubmit()`을 부르는 20줄 정도의 스크립트로 다시 만들면 됩니다. 저장소에 넣지 마세요.
- 이전 세션의 임시 파일(scratchpad)은 새 세션에는 없다고 가정하세요.
