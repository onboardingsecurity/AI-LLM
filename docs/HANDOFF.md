# 핸드오프 — 10번 과제: AI와 함께 쓰는 첫 논문 작성 (가설에서 결론까지)

다른 세션에서 이어서 작업할 때 가장 먼저 읽는 문서입니다. 작성일은 2026-10-27이고 브랜치는 `ai-first-paper-written-with-claude`입니다.

## 1. 프로젝트 한 줄 요약

관심 주제 하나를 골라 AI와 함께 가설을 세우고, 직접 데이터를 모아(직접 돌린 실험 또는 공개 데이터 분석) 검증한 뒤 논문 한 편으로 완성하는 10번 과제입니다. 제출물은 논문과 재현 패키지를 담은 ZIP 한 개이고, 수료 후 포트폴리오로 남습니다. 통과 기준은 T10-C01~C51이며 5개 카드(질문을 가설로, 논거 세우기, 실험 설계와 실행, 결과 해석, 논문으로 묶기)로 나뉩니다.

## 3. 주제 논의 경과 (카드 1 진행 중)

| 순서 | 내용 |
|---|---|
| 1 | Claude가 관심 분야 후보 5개를 제안함(AI 답변의 일관성, 프롬프트 작성 방식, AI의 할루시네이션, 보안 경고 분류, 공개 통계 겹쳐 보기). 사용자는 이 중에서 고르지 않고 자기 주제를 가져옴 |
| 2 | 사용자 제안: "호칭에 따른 물가 상승과의 연관 관계". 처음 호칭을 뉴스 표현·상품명·집단·AI 호칭 중 무엇인지 물었고, 사용자가 "2번(물가를 부르는 말)과 3번(집단)을 합친 것"이라고 답함 |
| 3 | 사용자가 더 정확히 설명함. 호칭은 **서비스·기술로 돈을 버는 직종**(과외, 미용사, 네일아트, 인테리어)이고 음식점·물건 판매는 아님. 물가 상승은 **"가격이 올랐다"는 단순한 뜻**(인플레이션·급등이 아님, 조금만 올라도 상승) |
| 4 | Claude가 직종 이름의 품목이 있다고 가정해 검색했는데, 사용자가 "품목이 있을 수 없다. 다들 기술직이고 **인건비**인 거지"라고 바로잡음 |
| 5 | Claude가 다시 정리한 이해(**사용자 확인 대기 중**): 호칭 = 인건비 비중이 큰 서비스. 가설의 모양 = "인건비가 오르면 인건비 비중이 큰 서비스의 가격이 물건 가격보다 더 잘 오르는가". 가격 상승 = 전년 같은 달보다 지수가 높으면 올랐다고 봄 |

- **아직 정해지지 않은 것**: 관심 분야 문장(C01), 후보 열 개 질문, 접은 후보 세 개와 이유(C02, C03), 최종 가설(C04~C07), 데이터 기간·범위(C08), 최종으로 고른 이유(C10). 모두 사용자가 정합니다.
- **사용자가 아직 답하지 않은 질문**: "인건비 비중이 큰 서비스의 가격과 인건비의 관계"라는 5번의 이해가 맞는지.
- **주의할 점(사용자에게 이미 말함)**: 인건비와 가격이 함께 오르는 자료만으로는 인건비가 올라서 가격이 오른 건지, 물가가 올라서 임금이 오른 건지 구분하지 못합니다. 그래서 결론은 "함께 움직이는가" 수준이어야 하고, "영향"이라고 단정하면 C40(원자료에 없는 주장 금지)에 걸릴 수 있습니다.

## 4. 데이터 출처 확인 상태 (모두 미확정)

| 확인한 것 | 상태 |
|---|---|
| 국가데이터처 「소비자물가조사」(소비 비중이 큰 458개 품목, 지출목적별 12개 대분류, 5년마다 개편, 2020년 기준) | e-나라지표 페이지에서 확인함. 연도 단위만 보임. 출처: <https://www.index.go.kr/unify/idx-info.do?idxCd=4226> |
| 미용료·학원비·가정교사료·주택수리비 같은 개별 품목이 있고 월별로 받을 수 있는가 | **확인하지 못함.** KOSIS에서 직접 확인 필요 |
| 상품과 서비스를 나누는 분류(품목성질별)가 제공되는가 | **확인하지 못함.** 외식이 서비스에 들어갈 수 있어 사용자의 "음식점은 판매 쪽" 구분과 어긋날 수 있음 |
| 한국소비자원 참가격의 개인서비스 요금 | 사이트가 화면 조작형이라 이 도구로 읽지 못함. 공개 데이터인지 모름 |
| 인건비 쪽 자료(최저임금, 서비스업 임금) | 정부 기관이 공개하는 것으로 알고 있으나 **아직 열어 보지 않음** |
| 다운로드에 로그인이 필요한가 | **확인하지 못함.** 계정이 필요하면 만들지 말고 다른 출처를 찾는 쪽이 안전(보안 S08, S12) |

- 사용자가 KOSIS에서 "소비자물가조사 품목별"을 직접 검색해 위 항목을 확인해야 합니다. Claude의 도구로는 이 화면을 읽지 못했습니다.
- 이 표의 "확인함"은 검색·열람으로 본 범위만 뜻합니다. 논문 참고문헌과 출처에 쓰려면 실물과 저자·연도를 다시 확인해야 합니다(C14, C20).

## 6. 남은 일 (순서대로)

1. **주제 확정(카드 1)**
   1. 사용자가 3번의 5번 이해가 맞는지 답합니다. 다르면 고친 뜻으로 다시 정리합니다.
   2. 확정된 관심 분야에서 확인해 볼 만한 질문 열 개를 Claude가 뽑습니다.
   3. 사용자가 데이터를 직접 모을 수 있는 것만 남기고, 각각 "무엇이 무엇에 영향을 준다" 한 문장으로 바꿉니다.
   4. 사용자가 하나를 고르고, 아까운 세 개를 이유와 함께 적습니다. 가설 문장에 측정 방법·반증 결과·기간 또는 범위를 붙입니다(C04~C08).
   5. AI와 다듬은 과정과 고른 이유를 적습니다(C09, C10). 과정은 실제로 오간 되묻기만 적습니다.
2. **문헌 검색(카드 2)**: 실물·저자·연도·초록을 확인한 것만 남기고, 뺀 것과 이유, 확인 방법을 기록합니다.
3. **실험 설계와 실행(카드 3)**: 설계 표를 먼저 확정하고, 시험 1회, 본 실행, 원자료 저장 순으로 합니다. 외부 데이터 내려받기는 사용자 승인 후 한 번만 합니다.
4. **결과 해석(카드 4)**, **논문 조립(카드 5)**, ZIP을 다른 폴더에 풀어 빠진 파일이 없는지 확인합니다.
5. 매 단계 끝에 "보안 점검, 요구사항 점검 수행해줘"로 확인하고 결과표로 보고합니다.

## 7. 작업 방침 (사용자와 합의한 것)

- **지어내지 않습니다.** 관심 분야, 후보 선택과 이유, 최종 가설, 작성자 이름, 결과 해석의 판단은 사용자 몫입니다. 확인하지 못한 문헌·출처·수치는 목록에서 빼고 이유를 적습니다(D03, D05).
- **한 번에 하나씩 짧게** 안내합니다. 정보를 한꺼번에 쏟지 않습니다.
- **파일을 만들거나 고치기 전에 먼저 묻고 허락을 받습니다.** 이번에는 사용자가 명세서 작성을 직접 요청해서 `docs/` 두 개를 만들었습니다.
- **커밋·푸시·제출은 사용자가 요청할 때만** 합니다. 요청받으면 보안·요구사항 점검을 먼저 돌려 ❌가 없을 때 진행하고, 작성자 주소는 noreply 주소로 기존 형식에 맞춰 논리 단위로 나눕니다. 커밋 메시지 끝에 점검 결과 요약과 Co-Authored-By 줄을 붙입니다.
- **프로젝트 폴더 밖 변경, 배포, 외부 서비스 설정, 외부 연결은 먼저 확인받습니다.**
- **점검 트리거**: "보안 점검, 요구사항 점검 수행해줘"라고 하면 두 docs 체크리스트를 실제로 실행해 확인하고, 요약 한 줄과 항목별 표(✅ ⏳ ➖ ❌)로 간단히 보고합니다. 실패가 있으면 이유와 통과하기 위한 대안을 함께 적습니다. 상태·근거 열은 사용자 승인 후 갱신합니다.
- **화면 문구 형식**: 이 과제에서 따로 정한 건 없습니다. 9번에서는 괄호를 쓰지 않고 문장 끝에 온점(질문은 ?)을 찍는 방침을 썼으니, 사용자에게 같은 방침을 쓸지 먼저 묻습니다.
