## 2. 일하는 방식 (사용자가 요구한 것)

- **한국어로 답합니다.** 한 번에 한 단계씩 짧게 안내합니다. 사용자가 "하나씩 차례대로"라고 하면 끝나면 다음으로 넘어갑니다.
- **커밋·푸시·배포는 사용자가 요청할 때만 합니다.** 요청받으면 먼저 보안 점검을 하고 ❌가 없을 때만 진행합니다. 올라갈 파일 목록은 먼저 보여 줍니다. 배포는 사용자가 직접 합니다.
- **사실을 지어내지 않습니다.** 사용자가 주지 않은 사실(삶의 사실, 동료, C16~C21 같은 기준)은 만들지 않고 묻습니다.
- **상태 ✅는 근거를 확인한 것에만 씁니다.** 사용자가 판단으로 통과시키면 "사용자 판단으로 통과"와 **판단 근거만** 적습니다("위험" 같은 표현은 쓰지 않기로 했습니다). 사용자가 직접 쓰기로 한 글(C14)은 쓰이기 전에 ✅로 바꾸지 않습니다.
- **사용자가 직접 정한 것은 바꾸자고 제안하지 않습니다**(7절).
- 점검 결과는 "요약 한 줄 + 항목별 표"로 보고하고, 개수는 직접 센 값만 말합니다. 문서의 상태 열 갱신은 사용자 승인 뒤에 합니다.
- 파일을 만들거나 고치거나 지우기 전에 사용자가 그 턴에 시킨 일인지 봅니다. 범위 밖이면 먼저 묻습니다. 프로젝트 폴더 밖은 건드리지 않고, 확인용 임시 파일은 세션의 임시 폴더에만 둡니다.
- 화면 확인은 합성 클릭이 아니라 크롬 개발자 도구(CDP)로 진짜 마우스·키 입력을 넣어서 합니다. `file://`뿐 아니라 `app/vercel.json`의 헤더를 붙인 로컬 서버에서도 한 번 확인합니다(`data:` 이미지와 인라인 `style` 속성은 배포 CSP에 막힙니다).

### G03에 대해

G03은 "AI에게 첫 판을 요청할 때 카드 1의 문장(앱 한 문장)을 그대로 넣는다"입니다. 카드 1은 ① 논문의 결론에서 결과 하나 고르기 ② "○○인 사람이 △△할 때 이 앱이 □□을 해 준다"로 쓰기 ③ 그 사람이 할 일 세 가지 적기이고, G03이 말하는 문장은 ②의 결과입니다. 문장·할 일 세 가지의 결과물은 REQUIREMENTS.md 0절에 있고 화면과 대응됩니다. 없는 것은 "첫 요청에 그 문장을 넣었다"는 **기록**뿐입니다. 이 PC의 Claude Code 대화 기록 22개를 검색했지만 앱 첫 판을 요청한 앞 세션의 기록은 없었고(현재 세션은 "다른 세션에서 진행하던 프로젝트를 이어서" 시작함), 사용자도 기억하지 못합니다. **그 앞 세션의 기록이 있는 곳에서 이어 일한다면** 그 세션의 첫 요청에 앱 문장이 들어 있는지 확인해 사실대로 알려 주세요. 확인되지 않으면 지어내지 말고 ➖로 둡니다. 이 항목은 번호 있는 통과 기준(BRB-C)이 아니라 번호 없는 조건(G)입니다.

## 8. 함정과 주의

- **git 작성자 주소**: 이 저장소의 git 설정 주소는 개인 메일입니다. 커밋마다 `git -c user.name=<이름> -c user.email=<noreply 주소>`로 덮어쓰세요. noreply 주소와 이름은 `git log --format='%an <%ae>' -3`의 최근 커밋에서 확인합니다. 커밋 메시지 끝에는 시스템이 알려 주는 공동 작성자 줄을 붙이고, 문서 커밋에는 `(✅ n / ⏳ n / ➖ n / ❌ n)` 합계를 붙입니다. 푸시 전에 원격과 로컬 상태를 보고 강제 푸시는 하지 않습니다.
- **줄바꿈**: 이 PC는 `core.autocrlf=true`라 작업 폴더 파일이 CRLF입니다(저장소에는 LF). 문서를 파이썬 등으로 고칠 때는 줄바꿈을 보존하세요(`newline=''`로 읽고 쓰기). 안 그러면 diff가 파일 전체로 커집니다.
- **셸**: bash 한 줄 `python -c`나 heredoc에 한글·역슬래시가 섞이면 깨지기 쉽습니다. 길면 스크립트 파일로 만들고, 역슬래시는 `chr(92)`로 쓰세요. 한글 출력은 `PYTHONIOENCODING=utf-8`이 필요합니다.
- **CSP**: `app/vercel.json`이 `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; …`라서 `data:` 이미지, 인라인 `style=` 속성, 외부 요청을 넣으면 배포에서만 깨집니다. 자바스크립트의 `el.style.x = …`는 됩니다. 화면 글은 모두 `textContent`로 넣습니다.
- **금지**: `.env`, 키, 실명(가게·시술자 이름 포함), 연락처, 로컬 경로를 저장소에 넣지 않습니다. `dist/`(ZIP)는 커밋하지 않습니다(`.gitignore`에 있음).
- **앱을 고치면** 테스트(`node tests/logic.test.js`), 커밋, 두 ZIP 재생성, 재배포, 배포 화면 확인을 다시 거칩니다.
- **보안 점검 범위**: 원격 저장소에 올라가는 파일과 배포된 `app/`입니다. 사용자의 PC 설정은 범위 밖입니다.
- 사용자가 "통과시켜줘"라고 해도 아직 없는 글이나 확인하지 못한 일은 ✅로 바꾸지 않습니다. "사용자가 직접 쓰기로 함"처럼 사실만 적고 이유를 설명합니다.
