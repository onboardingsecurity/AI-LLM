# 핸드오프 — 9번 과제: 나를 말하는 에이전트

다른 세션에서 이어서 작업할 때 가장 먼저 읽는 문서입니다. 작성일은 2026-10-26이고 브랜치는 `ai-agent-talking-about-me`입니다.

## 1. 프로젝트 한 줄 요약

매일 아침저녁 리추얼 기록에서 내 강점과 이야기를 찾는 에이전트를 만들고, 그 결과로 자기소개서 초안과 포트폴리오 뼈대를 서사 문서 한 개(`NARRATIVE.md`)로 완성하는 9번 과제입니다. 에이전트는 서비스가 아니라 규칙 한 벌(프롬프트)이고, ChatGPT의 임시 채팅에서 실행했습니다. 11번 소설과 12·13번 과제가 이 이야기를 이어받습니다.

## 2. 지금까지 한 일

1. **틀 만들기:** 요구사항 명세서(`docs/REQUIREMENTS.md`, T09-C01~C26), 보안 점검 리스트(`docs/SECURITY-CHECKLIST.md`, S01~S16), 서사 문서 틀(`NARRATIVE.md`), 에이전트 프롬프트(`agent/AGENT-PROMPT.md`), 읽기 전용 점검 스크립트(`scripts/check.mjs`)를 만들었습니다.
2. **카드 1 (기록 읽기):** 49일치 기록(2026-08-11~10-23)에서 동료가 한 말만 골라 12줄을 적었습니다. 밝음 4줄, 힘이 났던 날(아침·한 번도) 4줄, 놀란 순간(창의·아이디어) 4줄입니다.
3. **카드 2 (규칙):** 규칙 5개와 우선순위 한 줄을 사용자의 문장으로 확정했습니다. R4는 기록이 없는 곳을 채우되 문장 끝에 `[채움]`을 붙이고, 동료가 한 말은 채우지 않습니다.
4. **카드 3 (강점 지도):** ChatGPT가 뽑은 강점 셋을 기록 원문과 대조해 고쳤습니다. 지운 항목 4개와 이유를 남겼습니다.
5. **카드 4 (이야기):** 과정 이전의 고난(2016~2017, 경기도 포천 군 복무), 다시 일어난 날(2026-10-07), 더 나아진 나를 적고 3인칭 초안과 1인칭 완성본을 모두 남겼습니다. 동료 두 사람이 읽고 답했습니다.
6. **카드 5 (자기소개서·포트폴리오):** 자기소개서 초안(943자, 공백 제외)과 포트폴리오 뼈대(문서 안 목차)를 적었습니다. 첫 문장과 마지막 문장 내용은 사용자가 정했습니다.
7. **점검과 푸시:** 요구사항·보안 점검을 반복하고 논리 단위로 커밋해 푸시했습니다. 커밋 작성자는 noreply 주소입니다.

## 5. 파일과 점검 방법

| 파일 | 내용 |
|---|---|
| `NARRATIVE.md` | 제출하는 서사 문서(실명 포함, 8개 항목) |
| `agent/AGENT-PROMPT.md` | ChatGPT에 붙인 규칙과 질문 4개 |
| `docs/REQUIREMENTS.md` | 요구사항 명세서와 설계 결정 D01~D13 |
| `docs/SECURITY-CHECKLIST.md` | 보안 점검 리스트와 점검 결과 |
| `docs/HANDOFF.md` | 이 문서 |
| `scripts/check.mjs` | 읽기 전용 점검(`node scripts/check.mjs`, `req`, `sec`) |
| `records/` | 기록 원문 자리. 원문과 이름 목록은 저장소에 올라가지 않음 |

- **점검:** "보안 점검, 요구사항 점검 수행해줘"라고 하면 스크립트를 실제로 실행하고, 요약 한 줄과 항목별 표(✅ ⏳ ➖ ❌)로 짧게 보여 줍니다. 실패가 있으면 어디서 무엇이 실패했는지와 통과하기 위한 대안을 함께 적습니다.
- **로컬에만 있는 파일:** `records/`에 기록 원문(JSON)과 `names-to-hide.txt`(팀원 이름 6개, 한 줄에 하나)가 있어야 C02 날짜 대조와 S05 이름 대조가 됩니다. 새 환경에서는 사용자가 다시 넣어야 하며, 없으면 두 항목이 ➖로 나옵니다.
- **상태 갱신:** 문서의 상태·근거 열은 사용자 승인 후에 고칩니다.

## 6. 작업 방침 (사용자와 합의한 것)

- 커밋·푸시는 사용자가 요청할 때만 합니다. 먼저 보안·요구사항 점검을 돌려 ❌가 없을 때만 진행하고, 작성자는 noreply 주소를 씁니다.
- 한 번에 하나씩 짧게 안내하고, 파일을 고치기 전에 무엇을 바꿀지 말한 뒤 승인받습니다.
- 사용자만 아는 사실(실명, 고난 장면, 동료의 답, 마음)은 지어내지 않습니다. 내용은 사용자가 말하고 Claude는 받아 적거나 다듬습니다.
- 기록에서 고른 대목은 동료가 한 말만 씁니다(D12).
- 동료의 이름과 연락처는 서사 문서에 쓰지 않고 "동료 1, 2, 3"으로만 적습니다.
- 저장소는 공개이고 서사 문서에는 실명이 들어갑니다. 사용자가 판단했습니다(D11).
- 프로젝트 폴더 밖 변경, 배포, 외부 서비스 설정은 사용자가 직접 하거나 먼저 허락을 받습니다.

## 7. 제출문 초안

제출 화면의 두 칸에 쓸 내용입니다. 사용자가 읽고 고쳐 쓴 뒤 붙여 넣습니다.

### 재현·통과 확인 4가지 (권장)

```
어디서 확인하나요: 서사 문서(NARRATIVE.md) 안의 자기소개서는 5번 항목, 강점 지도는 3번 항목
무엇을 하나요(3단계 이내): 1) NARRATIVE.md를 연다 2) 3번 항목의 강점 지도와 5번 항목의 자기소개서를 읽는다 3) 3번 항목의 "지운 항목과 이유" 표와 4번 항목의 3인칭 초안·1인칭 완성본을 견주어 본다
무엇이 보이면 통과: 강점 3개 각각에 날짜 있는 장면, 동료가 말한 것, 지킨 가치, 1~8번 과제가 있고, 지운 항목 4개와 이유가 있고, 3인칭 초안과 1인칭 완성본이 모두 있고, 자기소개서에 이름·강점 셋·고비 한 장면·지금 하고 싶은 것이 있다
안 될 때: 제출한 파일은 NARRATIVE.md 한 개이고 로그인이나 비밀번호 없이 열린다. 열리지 않으면 파일 형식(MD, 일반 텍스트)을 텍스트 편집기로 열어 본다
```

