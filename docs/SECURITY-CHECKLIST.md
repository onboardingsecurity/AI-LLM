# 보안 점검 리스트 — 논문과 데이터를 외부로 옮기기 전에

**목적**: 논문·원자료·스크립트·AI 대화 기록을 GitHub나 제출 ZIP, 외부 AI 서비스로 옮기기 전에, 올라가면 안 되는 것이 들어 있지 않은지 점검합니다.
**범위**: 시스템 변경, 외부 연결, 키 값 노출과 관리, 개인정보, 데이터 출처와 내려받은 파일.
**점검 방법**: "보안 점검해줘"라고 하면 항목마다 명령을 실제로 실행해 확인하고(점검 스크립트를 만든 뒤에는 `node scripts/check.mjs sec`도 실행), 사용자만 확인할 수 있는 항목은 ➖로 두고 무엇을 확인해야 하는지 적습니다. 이전 결과를 그대로 옮기지 않습니다. 결과는 요약 한 줄과 항목별 표로 보고하고, 실패가 있으면 이유와 대안을 함께 적습니다. 이 문서의 상태·근거 열은 사용자 승인 후 갱신합니다.

> 참고한 형식: 브랜치 `ai-agent-talking-about-me`의 `docs/SECURITY-CHECKLIST.md`. 기록 원문·이름 목록 항목은 이 프로젝트에 맞게 줄이고, 내려받은 공개 데이터·문헌 출처·ZIP 내용 항목을 더했습니다.
> 모든 명령은 프로젝트 폴더에서 실행하며 읽기만 합니다.

## 상태 범례

| 표시 | 뜻 |
|---|---|
| ✅ 통과 | 확인했고 문제 없음 |
| ⏳ 진행중 | 해당 파일이나 작업이 아직 없어 확인을 미룸, 또는 알려진 위험에 대응이 남음 |
| ➖ 사용자 확인 | 사용자만 확인·결정할 수 있음 |
| ❌ 실패 | 올라가면 안 되는 것이 발견됨 |

### B. 개인정보

| ID | 점검 항목 | 확인 방법 | 상태 | 근거 |
|---|---|---|---|---|
| S04 | 이메일·전화번호·주민번호형·내 컴퓨터 경로가 제출물에 없다 | 올라갈 파일과 ZIP 내용 검색 | ⏳ | 논문·데이터·스크립트가 생긴 뒤 확인. 이 대화 기록에 나오는 계정 정보도 옮기지 않음 |

### C. 외부 연결과 데이터 출처

| ID | 점검 항목 | 확인 방법 | 상태 | 근거 |
|---|---|---|---|---|
| S07 | 작성한 코드가 외부로 연결하지 않는다(공개 데이터 내려받기 제외) | `fetch`, 소켓, URL, 네트워크 모듈 검색 | ⏳ | 스크립트 작성 후 확인. 내려받기가 필요하면 사용자 승인 후 한 번만 하고, 받은 뒤 스크립트는 로컬 파일만 읽게 함 |
| S08 | 공개 데이터는 기관이 직접 운영하는 출처에서 받았고 출처·받은 날짜가 기록돼 있다 | 방법 절, `data/` 대조 | ⏳ | 공개 데이터를 쓰기로 한 경우에만 해당. 직접 실험이면 해당 없음 |
| S09 | 내려받은 파일을 실행하지 않고 데이터로만 읽었다 | 받은 파일 형식 확인 | ⏳ | CSV·JSON 같은 데이터 형식만 받음. 실행 파일·매크로가 든 문서는 열지 않음 |
| S10 | 위험한 API(`eval`, `child_process`, `innerHTML` 등)를 쓰지 않는다 | 스크립트 검색 | ⏳ | 스크립트 작성 후 확인 |
| S11 | 외부 패키지에 의존하지 않는다 | `package.json` | ⏳ | 의존성 0개를 목표로 함. 필요하면 사용자에게 먼저 묻고 버전을 고정 |
| S12 | 제출물에 적힌 URL이 로그인 없이 열린다 | URL 목록 출력, 사용자가 시크릿 창에서 확인 | ➖ | 참고문헌 URL을 포함해 사용자가 시크릿 창에서 열어 봐야 함(T10-C51) |
| S13 | 외부 AI 서비스로 보내는 내용의 범위와 서비스의 학습 설정을 확인했다 | 사용자 확인 | ➖ | 직접 AI에게 실험을 돌린다면 보내는 프롬프트에 개인정보가 없는지, 서비스의 데이터 학습 설정이 꺼져 있는지 사용자가 확인 |
