# 템플릿 데이터 구조

IndexedDB에 저장하는 템플릿 한 건의 항목이다. 5단계의 JSON 내보내기와 가져오기 검증도 이 정의를 기준으로 한다.
검사 코드는 js/app.js의 `validateTemplate()`이다. 항목을 바꾸면 이 문서와 그 함수를 함께 고친다.

- 데이터베이스 `meme-card-studio`, 버전 1, 저장소 `templates`, 키 `id`
- 아래 항목은 모두 필수다. 없거나 형식이 다르면 잘못된 데이터로 본다.

| 항목 | 형식 | 조건 | 설명 |
|---|---|---|---|
| id | 문자열 | 비어 있지 않음 | 만들 때 한 번 부여하는 고유 번호(UUID). 수정과 삭제는 이 값으로만 대상을 찾는다. |
| version | 숫자 | 1 | 데이터 구조 버전 |
| name | 문자열 | 공백 제외 1~40자 | 템플릿 이름. 비워서 저장하면 "템플릿 N"으로 자동 부여 |
| memo | 문자열 | 0~100자 | 메모. 없으면 빈 문자열 |
| createdAt | 문자열 | ISO 8601 시각 | 만든 시각. 수정해도 바뀌지 않는다. |
| updatedAt | 문자열 | ISO 8601 시각 | 마지막으로 고친 시각 |
| ratio | 문자열 | `"1:1"`, `"4:5"`, `"9:16"` 중 하나 | 화면비 |
| text | 문자열 | 0~200자 | 문구. 줄바꿈은 `\n`. 화면에서 입력할 수 있는 길이는 50자이고, 저장 데이터는 예전에 저장한 값(최대 200자)도 읽을 수 있도록 200자까지 허용한다 |
| size | 숫자 | 16~240 | 문구 크기(1080 기준 px). 화면에서 줄여 그린 값이 아니라 슬라이더 값. 화면에서 조작할 수 있는 범위는 16~100이고, 저장 데이터는 예전에 저장한 값(최대 240)도 읽을 수 있도록 240까지 허용한다. 100보다 큰 값은 불러올 때 100으로 줄여 쓴다 |
| color | 문자열 | `#rrggbb` | 문구 색 |
| x | 숫자 | 0~1 | 문구 중심의 가로 위치(캔버스 폭 대비) |
| y | 숫자 | 0~1 | 문구 중심의 세로 위치(캔버스 높이 대비) |
| image | 객체 또는 null | 아래 표 | 이미지가 없는 상태는 `null`. 항목 자체가 없으면 잘못된 데이터 |

## image 객체

| 항목 | 형식 | 조건 | 설명 |
|---|---|---|---|
| name | 문자열 | | 불러올 때의 파일 이름 |
| width, height | 정수 | 1 이상 | 이미지 화소 크기 |
| mime | 문자열 | `"image/png"` | 저장 형식. 불러온 이미지를 원본 화소 그대로 다시 그려 PNG로 저장한다. EXIF 등 메타데이터는 남지 않고 투명도는 유지된다. |
| blob | Blob | 크기 1바이트 이상 | 이미지 본체(IndexedDB에서). JSON으로 내보낼 때는 이 자리를 Base64 문자열로 바꿔 담는다(5단계에서 확정). |

## 동작 규칙

- 새로 저장: 현재 편집 상태(이미지, 문구, 위치, 크기, 색, 화면비)와 입력한 이름, 메모로 새 `id`를 만들어 추가한다.
- 수정 저장: 선택한 템플릿의 `id`로 찾아 편집 상태와 이름, 메모를 덮어쓴다. `id`, `createdAt`은 유지하고 `updatedAt`만 새로 쓴다. 그 사이 대상이 삭제되었으면 새로 만들지 않고 알린다.
- 삭제: `id`로 찾아 지운다. 확인 창에서 취소하면 지우지 않는다.
- 불러오기: 저장된 데이터를 검사하고 이미지를 해독한 뒤에만 현재 편집 상태를 바꾼다. 실패하면 현재 편집 상태를 그대로 둔다. 확인 창은 없다(사용자 요청). **불러올 때 바뀌는 것은 이미지와 화면비뿐이고, 문구(내용, 크기, 색, 위치)는 지금 편집 중인 것을 그대로 유지한다**(사용자 요청, 기본 템플릿과 직접 만든 템플릿 모두). 저장된 문구 등은 템플릿 데이터에 그대로 남고, "선택한 템플릿 수정 저장"을 누르면 지금 문구로 바뀐다.
- 목록: 화면 상태가 아니라 저장소에서 다시 읽어 그린다.

## JSON 파일 형식 (내보내기와 가져오기)

파일 이름은 `meme-card-templates-YYYYMMDD-HHMMSS.json`이다. 내보내기는 저장된 템플릿 전체를 담는다.

```json
{
  "format": "meme-card-studio-templates",
  "version": 1,
  "exportedAt": "2026-09-20T02:08:30.000Z",
  "templates": [ { "...": "위 표의 항목 그대로. 단 image.blob 자리에 image.data(Base64 문자열)" } ]
}
```

| 최상위 항목 | 형식 | 조건 |
|---|---|---|
| format | 문자열 | `"meme-card-studio-templates"` |
| version | 숫자 | 1 |
| exportedAt | 문자열 | 참고용. 검사하지 않는다. |
| templates | 목록 | 1건 이상 |

각 템플릿은 위 표와 같은 항목을 모두 갖춰야 한다. 다른 점은 이미지 본체뿐이다: `image.blob` 대신 `image.data`(비어 있지 않은 Base64 문자열, 실제로 PNG여야 하고 `width`, `height`와 실제 크기가 같아야 한다). 표에 없는 항목은 무시한다.

### 가져오기 규칙

1. 읽기: 빈 파일이거나 100MB를 넘으면 거부한다.
2. 문법(파싱): JSON 문법이 틀리면 거부하고 가능하면 줄과 글자 위치를 알려 준다.
3. 파일 구조: `format`, `version`, `templates`를 확인한다. 없는 것(필수 항목 없음)과 값이 틀린 것을 구분해 알려 준다.
4. 항목 전체 검사: 모든 템플릿을 끝까지 검사하고 문제를 전부 모아 "몇 번째 항목(이름)의 어느 항목이 왜 문제인지"를 알려 준다. 파일 안에서 id가 겹쳐도 거부한다.
5. 저장: 위 단계를 모두 통과했을 때만, 한 트랜잭션으로 모두 저장한다. **어느 단계에서든 문제가 있으면 저장소에 아무것도 쓰지 않는다.** 정상인 항목만 골라 저장하지 않는다.
6. id: 파일의 id를 그대로 쓰되, 이미 저장된 id와 겹치는 항목만 새 id로 추가한다. 기존 템플릿은 덮어쓰지 않는다.
7. 결과에는 가져오기 전후 건수를 함께 표시한다.

검사 코드는 내보내기와 가져오기가 함께 쓰는 `validateTemplate(t, form)`이다(form은 저장된 모습 `"stored"` 또는 파일 안의 모습 `"file"`).

## 기본 템플릿

열 때마다 이 구조의 템플릿 3개 중 저장소에 없는 것을 채운다(js/app.js의 `ensureDefaultTemplates()`). 모두 있으면 이미지를 받지 않는다.

| id | 이름 | 화면비 | 이미지 |
|---|---|---|---|
| default-template-1 | 기본 템플릿 1 | 1:1 | assets/templates/template-image1.png (1796×876) |
| default-template-2 | 기본 템플릿 2 | 4:5 | assets/templates/template-image2.png (1796×876) |
| default-template-3 | 기본 템플릿 3 | 9:16 | assets/templates/template-image3.png (1796×876) |

- 문구는 "문구를 끌어서 위치를 옮기세요."와 "화살표 키로도 옮길 수 있습니다." 두 줄(줄바꿈 포함), 크기 26, 색 #222222, 위치 x 0.5, y 0.7(가운데에서 아래쪽)이다. 이미 저장된 기본 템플릿 중 수정 저장하지 않은 것(updatedAt = createdAt)은 열 때 이 값으로 맞춘다.
- 이미지는 파일 그대로(PNG) 저장한다. 다른 템플릿처럼 다시 그려 저장하지 않는다(파일에 이미 메타데이터가 없다).
- 삭제할 수 없으므로 없어질 일이 없지만, 예전에 지웠거나 저장소가 비었으면 다음에 열 때 다시 채운다(수정한 것은 그대로 둔다). 넣었다는 표시는 남기지 않는다(localStorage를 쓰지 않는다).
- 일반 템플릿과 거의 같다. 수정, 불러오기, JSON 내보내기·가져오기가 된다. **삭제 버튼은 없고 코드에서도 삭제를 막는다**(사용자 요청). 사용자가 만든 템플릿은 삭제할 수 있다(T03-C20).
- JSON에 default-template-1~3과 같은 id가 든 항목을 가져올 때 이미 그 id가 저장소에 있으면 다른 템플릿처럼 새 id를 받아 추가되고, 그 복사본은 삭제할 수 있다.
- 이미지는 넓은 배경 가운데에 캐릭터가 있어서 화면비를 바꿔도 캐릭터가 잘리지 않는다.
