## 이어갈 때 지킬 것
1. **지어내지 않는다(D03).** 주제, 가설, 접은 이유, 작성자, 결과 판단은 사용자가 정한다. 확인하지 못한 문헌과 수치는 목록에서 뺀다.
2. **파일을 만들거나 고치기 전에 묻는다.** 사용자가 "요구사항과 보안에 위배되지 않으면 수행해"라고 위임하면 점검 후 진행하고, 한 일을 분명히 보고한다.
3. **한 번에 하나씩 짧게 안내한다.** 선택지는 1, 2, 3 번호를 붙여 줄바꿈한다.
4. **가게 이름은 파일에 쓰지 않는다(D06).** 이름 대조의 기준 자료는 사용자가 프로젝트 밖에 따로 보관하는 가게 링크 목록이다.
5. **비교용 메뉴 기준(2-2절 7번)은 결과를 본 뒤에 바꾸지 않는다.** 바꾸면 변경 기록(C30)에 이유와 함께 적는다.
6. **내용 점검(D11).** 주제, 가설, 해석을 쓰기 전에 REQUIREMENTS.md 2-1절 기준으로 먼저 점검한다. "높여 부르는 호칭", "함께 움직이는가"처럼 판단이 들어가지 않는 말을 쓴다. "새로오픈" 가게를 한계에 적을지는 사용자가 적지 않기로 했다.
7. **이미지에서 읽은 숫자는 오독이 있을 수 있다.** A-6의 "40,0" 표기 7행은 아직 미확인이다(REQUIREMENTS.md 알아 둘 점 3번).
8. **커밋 형식**: 한국어 메시지, 논리 단위로 나누고, 끝에 점검 결과 요약을 붙인다. 개인 이메일이 드러나지 않도록 noreply 주소를 지정한다. 형식은 WORKING-AGREEMENTS.md 5번에 있다.
9. 점검을 요청받으면 "보안 점검, 요구사항 점검"을 실제로 돌려 결과표로 보고한다. 이전 결과를 그대로 옮기지 않는다.
