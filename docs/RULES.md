# 규칙

## 작업 규칙

1. 파일 생성·수정·삭제는 먼저 사용자에게 묻고 허락받은 뒤에만 한다.
2. 작업은 이 프로젝트 폴더 안에서만 한다. 폴더 밖(시스템 설정, 스케줄러 등) 변경은 먼저 확인받는다.
3. 요구사항은 사용자가 차례로 말하는 순서대로 `docs/REQUIREMENTS.md`에 추가한다. 임의로 추가·삭제하지 않는다.
4. 외부에서 받기로 한 자료를 못 찾아도 지어내지 말고 사용자에게 다시 확인한다.
5. 요청한 작업이 끝나면 점검하고, 결과를 통과/실패와 근거로 보고한다.
6. 문서는 `docs/`의 md 파일로만 관리한다. 점검용 스크립트·설정 파일은 만들지 않는다.

## 인수인계 규칙 (세션이 끊겨도 이어지게)

1. 세션을 마치기 전에 지금 상태, 끝난 일, 남은 일, 다음 첫 행동을 문서에 남긴다.
2. 새 세션은 대화 기억이 아니라 `docs/` 문서와 점검 결과만 근거로 작업을 재개한다.
3. 결정 사항과 그 이유는 문서에 적는다. 대화에만 있는 결정은 없는 것으로 본다.

## 점검 규칙

- 점검 호출 문구: 사용자가 "점검 수행해줘"라고 하면 `docs/CHECKLIST.md`를 기준으로 보안 점검과 요구사항 점검을 함께 수행한다.
- 결과는 항목마다 `통과` 또는 `실패`로 알린다. 실패 항목에는 문제, 대안, 해결책을 함께 적는다.
- 하나라도 실패하면 전체 결과는 실패다.
- 점검 기준을 느슨하게 바꾸는 변경은 사용자 승인 후에만 한다.
