# 요구사항 명세서 — 9번 과제: 나를 말하는 에이전트

> **작성 경위**: 구현 전에 먼저 쓴 문서입니다. 출처는 ① 사용자가 전달한 주제 설명, ② 카드 1~5의 통과 기준(T09-C01~C26), ③ 구현 전에 사용자와 합의한 방향입니다. 통과 기준의 문장은 사용자가 준 원문을 줄여 적었고, 번호는 원문 그대로입니다.
>
> **점검 방법**: "요구사항 점검해줘"라고 하면 `node scripts/check.mjs req`를 실제로 실행하고, 스크립트가 못 보는 항목은 아래 "확인 방법"대로 직접 확인해 상태를 다시 판정합니다. 이전 결과를 그대로 옮기지 않고, 사용자만 확인할 수 있는 항목은 ➖로 두고 무엇을 확인해야 하는지 적습니다. 결과는 요약 한 줄과 항목별 표로 보고하고, 실패가 있으면 어디서 무엇이 실패했는지와 통과하기 위한 대안을 함께 적습니다. 문서의 상태·근거 열은 사용자 승인 후 갱신합니다.

## 상태 범례

| 표시 | 뜻 |
|---|---|
| ✅ 통과 | 근거를 확인함 |
| ⏳ 진행중 | 일부는 확인했고 남은 작업이 있음 |
| ➖ 미확인 / 사용자 확인 | 아직 확인하지 못했거나, 사용자만 확인·결정할 수 있음 |
| ❌ 실패 | 확인했더니 기준을 만족하지 못함 |

## 0. 주제와 범위

- **주제**: 매일 아침저녁으로 남긴 리추얼 기록에서 내 강점과 이야기를 찾는 나만의 에이전트를 만들고, 그 결과로 자기소개서 초안과 포트폴리오 뼈대를 완성한다.
- **성격**: 연습이 아니라 실제로 쓸 이력서의 첫 판이다. 10번 논문, 11번 소설, 12·13번 과제로 이어진다.
- **에이전트**: 잘 짜인 프롬프트 한 벌이다(`agent/AGENT-PROMPT.md`). 무료 AI 서비스의 새 대화에 규칙을 넣고 기록 파일을 붙여 쓴다.
- **제출물**: 서사 문서 파일 한 개(`NARRATIVE.md`). 포트폴리오 뼈대는 문서 안의 목차로 둔다.
- **점검 도구**: `scripts/check.mjs`는 서사 문서와 프로젝트 파일을 읽기만 한다. 서버, 계정, 외부 연결, 키는 없다.

확인 방법의 "스크립트"는 `node scripts/check.mjs req`입니다. 서사 문서의 체크 칸(`[x]`)은 사용자가 직접 표시합니다.

## 2. 합의된 설계 결정

사용자가 "전달한 요구사항 기반으로 진행"하라고 한 범위에서 정한 항목입니다. 바꾸고 싶으면 알려 주세요.

| ID | 결정 | 이유 |
|---|---|---|
| D01 | 서버, 계정, 데이터베이스, 외부 연결, 키를 쓰지 않는다. 에이전트는 프롬프트 한 벌이다 | 주제가 "프롬프트 한 벌이어도 충분"하다고 허용함. 다룰 비밀이 없어 보안 범위가 작아짐 |
| D02 | 제출물은 루트의 `NARRATIVE.md` 한 개이고, 점검 틀(제목·표·체크 칸)을 스크립트가 읽는다 | C18 한 파일 제출, 자동 점검 |
| D03 | 리추얼 기록 원문은 `records/`에 두고 저장소에서 제외한다 | 동료 이름 등 다른 사람의 정보가 들어 있어 올라가면 안 됨(C26) |

## 3. 건너뛴 번호
