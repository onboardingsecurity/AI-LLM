# 요구사항 명세서

과제 3 또는 4의 작은 개선 하나를 두 AI 세션이 차례로 이어서 완성하고, 새 대화가 인수인계 문서만으로 작업을 재개하는지 시험한다. 여러 LLM을 연계해 사용할 수 있는 기능을 만든다.

## 작성 방법

- 사용자가 요구사항을 말할 때마다 아래 표에 한 줄씩 추가한다. ID는 사용자가 준 ID를 그대로 쓰고 재사용하지 않는다.
- 점검 방법은 `docs/CHECKLIST.md`를 따른다. 통과 근거는 `records/` 아래 md 기록이다.
- 상태: `대기`(아직 안 함), `진행`, `완료`. 완료는 점검이 통과해야 선언할 수 있다.

## 카드별 남길 것 (카드 1~5 요약)

1. 같은 문제, 같은 검사: 초기 검사 10개와 공통 사용 상한, 같은 최초 요청, AI A 시작 시각과 시작 소스
2. AI A 작업 멈추기: 멈춘 소스와 검사 결과, 실제 사용량, 인수인계 문서. 순서는 현재 버전 ID → 실행 명령 → 첫 실패 검사 → 다음 행동
3. 일곱 칸 인수인계: 문서와 새 폴더 재현 결과. 확인 순서는 필요 버전 → 설치 명령 → 환경값 예시 → 작업 폴더
4. 새 대화가 이어받기: AI B에 준 저장소와 문서, 최종 검사·사용량. AI B가 앞 대화를 요구하면 대화 전문은 주지 않고 문서의 현재 상태 보완 → 첫 실패 검사 추가
5. 이름 가리고 비교: 가린 비교표(시간·요청/호출·오류·통과 수), 전체 작업 기록, 도구 선택 기준. 재작업량은 제출 뒤 로컬 채점기가 계산하므로 수기로 넣지 않는다

## 기록 파일 (통과 근거)

실제로 일어난 일을 그대로 적는다(사후에 맞춰 고치지 않는다). 시각은 `2026-10-11 19:30`처럼, 버전 ID는 저장소의 커밋 해시로 적는다.

| 파일 | 내용 |
|------|------|
| `records/plan.md` | 고정 시각, 선택한 기능, 최초 요청, 시작 소스 주소, 검사 10개(ID·입력·기대값), 공통 시간 상한, 공통 요청·호출 수 상한 |
| `records/log.md` | A 시작 → A 종료·인수인계 → B 시작 → B 종료 순서의 시각·버전 ID, AI별 서비스·모델·실제 작업시간·요청/호출 수 |
| `records/results_a.md`, `records/results_b.md` | 검사 10개 최종 PASS/FAIL, 실행 회차별 결과, 오류 회차 수 |
| `records/checks_final_b.md` | AI B 종료 시점의 검사 10개(삭제·완화·기대값 변경 비교용) |
| `docs/HANDOVER.md` | 일곱 칸 인수인계 문서(맨 위에 `버전 ID: <해시>`) |
| `records/handover_received.md` | AI B가 받은 문서 사본 |
| `records/handover_gaps.md` | `누락: 없음` 또는 수정 전·수정 후 내용 |
| `records/repro.md` | 새 폴더 재현 결과 |
| `records/urls.md` | 제출 URL과 시크릿 창 확인 결과 |
| `records/comparison.md` | 이름을 가린 비교표(시간·요청/호출·오류·통과 수) |
| `records/submission.md` | 도구 선택 기준 한 문장, 짧은 확인 방법, 제출문 3구분 |
