> **작성 경위**: 구현을 먼저 시작한 뒤 사후에 정리한 문서입니다. 출처는 ① 사용자가 전달한 주제 설명, ② 카드 1~5의 통과 기준(T08-C01~C53), ③ 구현 중 사용자와 합의한 설계 결정입니다. 통과 기준의 문장은 사용자가 준 원문을 줄여 적었고, 번호는 원문 그대로입니다.
>
> **점검 방법**: "요구사항 점검해줘"라고 하면 아래 표의 "확인 방법"을 실제로 실행해 상태를 다시 판정합니다. 이전 결과를 그대로 옮기지 않고, 사용자만 확인할 수 있는 항목은 ➖로 두고 무엇을 확인해야 하는지 적습니다. 결과는 요약 한 줄과 항목별 표로 보고하고, 문서의 상태·근거 열은 사용자 승인 후 갱신합니다.

## 0. 주제와 범위

- **주제**: 내 소개 페이지에 패스키를 달아 비밀번호 없이 나만 들어가기
- **바탕**: 1번 과제의 자기소개 페이지(`index.html`)를 그대로 두고 이어 붙인다.
- **하는 일**: 나만 볼 수 있는 자리를 하나 만들고 패스키로만 잠근다. 비밀번호는 만들지 않는다.
  - 등록: 기기가 키 한 쌍을 만들어 **공개키만** 서버로 보내고, 개인키는 기기 밖으로 나가지 않는다.
  - 로그인: 서버가 매번 새 질문(challenge)을 보내고, 기기가 서명해 답한다.
  - 분실 대비: 패스키를 두 개 등록하고, 하나를 지운 뒤에도 들어갈 수 있는지 확인한다.
- **공개 영역**: 지금처럼 누구나 본다. 잠그는 것은 새 자리뿐이다.
- **내용**: 실제 연락처·신분증 번호 같은 진짜 개인정보는 넣지 않고, 만들어 넣은 내용을 쓴다.

## 2. 합의된 설계 결정

사용자가 "보안에 문제되거나 요구사항에 해가 되지 않으면 전부 추천대로"로 승인한 항목입니다.

| ID | 결정 | 이유 |
|---|---|---|
| D01 | Node.js(Express 5) + express-session + `@simplewebauthn/server` | 비공개 내용을 서버가 로그인 뒤에만 내려 주려면 서버가 필요(C16~C18). 서명 검증은 검증된 라이브러리에 맡김 |
| D02 | 첫 등록은 서버 콘솔에 나오는 **일회용 설정 코드**가 있어야 함. 등록 한 번마다 바뀜(환경변수 `SETUP_CODE`로 고정 가능) | 아무나 먼저 등록하는 것을 막음 |
| D03 | 마지막 패스키는 삭제할 수 없음(서버 409, 화면 버튼 잠김) | 계정이 잠기는 일을 막음(C46) |
| D04 | 계정 2개(`account-a`, `account-b`), 지어낸 비공개 항목 3개씩 | 카드 5 |
| D05 | 로그인은 계정 선택 없이 기기의 패스키 목록에서 고르는 방식(discoverable credential) | 비밀번호·아이디 입력 없음. 지운 패스키 시도가 서버에서 401로 보임 |
| D06 | 로그인 후 식별은 서버 세션 + `HttpOnly` `SameSite=Lax` 쿠키(`sid`, 30분). 세션은 배포에서 Supabase `sessions` 테이블(세션 ID는 해시로만), 내 컴퓨터에서는 메모리 | C32 |
| D07 | 로그인에 쓴 패스키를 지우면 그 패스키로 연 세션도 무효 | 기기 분실 시 세션도 끊기게 |
| D08 | 질문(challenge)은 저장소에 보관하고 세션에는 값만 둠, 2분 만료, 한 번 꺼내면 삭제(Supabase는 `DELETE ... RETURNING` 한 문장) | 재사용 방지(C31), 동시에 두 번 와도 한 번만 |
| D09 | 상태 변경 요청은 `Origin`이 서버 주소가 아니면 403 | 다른 사이트의 요청 차단 |
| D10 | 개인키가 서버로 오지 않음. 서버 저장소에는 공개키·식별자·이름·카운터·날짜만 | C21~C23 |
| D11 | 가상 인증기로 서버를 시험하는 `npm test`를 둠. 실제 기기 확인과 구분해서 적음 | 실제 기기로 재현하기 어려운 시나리오(질문 재사용 등) |
| D12 | 배포는 **Vercel + Supabase**. Supabase는 저장소로만 쓰고(Supabase Auth 안 씀) 서버만 서비스 롤 키로 접근. 모든 테이블에 RLS를 켜고 정책은 만들지 않음 | Vercel 함수는 메모리·파일이 유지되지 않음. 공개 키로는 아무 행도 못 읽게 함 |
| D13 | 저장소 계층(`store.js`)을 분리. Supabase 키가 있으면 Supabase, 없으면 파일·메모리. **Vercel에서 키가 없으면 시작하지 않음**, Supabase 사용 시 `SESSION_SECRET`·`SETUP_CODE` 환경변수 필수 | 배포에서 조용히 메모리로 떨어져 패스키가 사라지는 일을 막음 |
| D14 | `index.html`·`auth.js`는 `public/`으로 옮겨 Vercel이 정적으로 제공 | 함수 응답 한도 4.5MB < index.html 5.7MB |
