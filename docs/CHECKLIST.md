# 점검 목록

"점검 수행해줘"라고 하면 아래 두 가지를 모두 확인하고 통과/실패로 보고한다. 실패 항목은 문제, 대안, 해결책을 함께 적는다.

## 1. 보안 점검

프로젝트 안의 모든 파일(`.git` 제외)을 검색해 확인한다. 보고에 키 값은 앞 4글자만 쓴다.

| ID | 분류 | 점검 내용 | 통과 조건 |
|----|------|-----------|-----------|
| S01 | 키 값 | API 키·토큰·비밀번호·개인 키가 적혀 있는가 | 0건 |
| S02 | 키 값 | `.env` 등 비밀 파일이 있고 `.gitignore`로 보호되지 않는가 | 없거나 보호됨 |
| S03 | 개인정보 | 이메일·전화번호·주민등록번호·카드번호·실명이 있는가 | 0건 (가짜 예시값은 허용) |
| S04 | 시스템 변경 | 폴더 밖 경로 접근, 관리자 권한, 스케줄러·시스템 설정 변경, 전역 설치가 있는가 | 0건 |
| S05 | 외부 연결 | 승인하지 않은 외부 주소·네트워크 호출이 있는가 | 0건 |

실패 시 기본 해결: 값을 지우고 환경 변수나 가짜 값으로 바꾼다. 이미 노출된 키는 폐기·재발급한다. 외부 연결이 필요하면 사용자 승인 후 `RESTRICTIONS.md`에 적는다.

## 2. 요구사항 점검

`docs/REQUIREMENTS.md`의 요구사항을 하나씩 확인한다.

- 통과 근거는 `records/` 아래 기록과 실제 저장소(버전 ID)다. 근거를 못 찾으면 실패다.
- `완료`로 표시된 것이 근거가 없으면 실패다. 상태를 `진행`으로 되돌린다.
- 실패 시 문제(어떤 근거가 없거나 다른지), 대안, 해결책(무엇을 만들거나 고칠지)을 적는다.

## 보고 형식

```
[통과/실패] ID 이름
  문제: ...
  대안: ...
  해결: ...
종합: 통과/실패 (보안 n/5, 요구사항 n/전체)
```
