# 작업 방식 합의 — 10번 과제 (2026-10-28)

사용자가 정한 작업 방식이다. 상태가 바뀌는 문서가 아니라 계속 지키는 규칙이라 `docs/HANDOFF.md`와 따로 둔다. 새 세션에서는 사용자가 알려 주는 위치의 이 문서와 `docs/HANDOFF.md`, `docs/REQUIREMENTS.md`를 먼저 읽고 시작한다.

1. **프로젝트 밖에 기억을 남기지 않는다.** 이어서 할 내용은 프로젝트 안 문서에 적는다(사용자 요청).
2. **한 번에 하나씩 짧게 안내한다.** 선택지는 한 줄에 늘어놓지 않고 1, 2, 3 번호를 붙여 줄바꿈한다. 답을 못 받은 질문은 "아직 답을 못 받은 것"으로 모아 끝에 다시 적는다.
3. **파일을 만들거나 고치기 전에, 그리고 프로젝트 폴더 밖을 바꾸기 전에 먼저 묻고 허락받는다.** 허락 없이 파일을 만들어 절차를 어긴 적이 있다.
4. **지어내지 않는다(D03).** 확인하지 못한 문헌·출처·수치는 목록에서 빼고 이유를 적는다.
5. **커밋·푸시·제출은 사용자가 요청할 때만 한다(D10).** 요청받으면 보안·요구사항 점검을 먼저 돌려 ❌가 없을 때 진행한다. 커밋은 논리 단위로 나누고 메시지는 한국어로 쓰며 끝에 점검 결과 요약을 붙인다. 개인 이메일이 노출되지 않도록 커밋마다 noreply 주소를 지정한다(`git -c user.name=onboardingsecurity -c user.email=326323901+onboardingsecurity@users.noreply.github.com commit`).
6. **`.claude/settings.json`**(메시지마다 내용 점검 규칙을 붙이는 훅 설정)은 사용자가 `.gitignore`에 넣지 않기로 했다. 커밋 전에 `command` 줄이 고정 문구를 출력하는 `printf` 한 줄뿐인지 사용자가 읽어 확인하고(S16), 제출 ZIP에는 넣지 않는다. `.gitignore`에는 `.claude` 관련 줄을 두지 않는다.
7. **이어서 할 내용은 `docs/HANDOFF.md`에 적는다.** Claude가 쓰고 사용자 승인으로 갱신한다(2026-10-28에 사용자가 직접 만들기로 한 방침을 바꿈).
8. **시험이나 점검을 돌린 뒤에는 임시 데이터를 항상 지운다.** 임시 폴더, 띄운 시험 서버와 브라우저 프로세스, 시험용 DB 행을 성공·실패와 관계없이 정리한다. 이미 남은 것은 지우기 전에 목록을 보여 주고, 시스템 임시 폴더 안에서 Claude가 만든 것만 지운다. 시험이 실제 기록 파일에 섞이지 않게 한다.
9. **화면에 보이는 문구(스크립트 출력 등)의 형식은 이 과제에서 따로 정하지 않았다.** 만들기 전에 먼저 묻는다(9번 과제에서는 괄호를 쓰지 않고 문장 끝에 온점, 질문은 ?).
10. **가게 가격 이미지**: 이름은 파일에 쓰지 않고 이름과 메뉴·가격으로 중복부터 대조한다. 호칭 분류는 사용자 판단을 따른다. 비교용 메뉴를 정하기 전에는 집단별 가격을 비교하지 않는다.
