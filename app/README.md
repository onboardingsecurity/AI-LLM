# 대구! 갈래? 말래?

손님이 호칭과 서비스 가격을 넣으면, 논문 속 같은 호칭 가게들의 가격과 견주어 어디쯤인지 알려 주는 앱입니다. 가게 두 곳을 넣으면 가격 차이가 기준 금액을 넘는지 알려 줍니다.

논문: 네일샵 시술자 호칭 유형과 손 젤 원톤 가격 수준의 관계: 대구 지역 탐색적 비교

## 실행 방법

설치할 것이 없습니다.

1. 압축을 풀고 `index.html`을 더블클릭해서 브라우저로 엽니다.
2. 직업 선택 화면에서 첫 번째 그림(손톱, 네일)을 누릅니다. 나머지 다섯 칸은 아직 열리지 않았습니다. 자물쇠가 붙은 요리사 vs 쉐프와 개발자 vs 엔지니어는 누르면 "준비중" 안내가 뜨고, 아래 세 칸은 완전히 잠겨 있어 눌러도 반응이 없습니다.
3. 서비스 선택 화면에서 "손 젤 원톤"을 누릅니다. 지금은 논문이 판단한 서비스가 이것 하나뿐입니다. 서비스가 늘어나면 이 화면에 칸이 늘어나고, 논문에서 다루지 않은 서비스는 잠긴 칸으로 보입니다.
4. 가게 1의 호칭을 목록에서 고른 뒤 가격을 넣고 "알아보기"를 누릅니다. 가게 2는 비교할 가게가 있을 때만 넣습니다(호칭과 가격을 모두 넣거나 모두 비워 둡니다).
5. "계..산..중" 창이 잠깐 뜬 뒤 결과 화면으로 넘어갑니다. 맨 아래 걸어가는 사람 버튼을 누르면 한 화면씩 뒤로 돌아갑니다(결과 화면에서는 입력 화면으로, 입력해 둔 값은 그대로 남습니다).

## 환경 변수

없습니다. AI 서비스를 부르지 않고 브라우저 안에서만 계산하므로 키가 필요 없습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `index.html`, `style.css` | 화면과 스타일 |
| `script.js` | 화면 동작(알림 창, 클릭 효과, 직업·서비스 고르기, 호칭 선택 목록, 계산 중 창, 결과 그리기) |
| `logic.js` | 판단 규칙(가격 범위 위치, 가격 차이와 기준 금액 비교, 소비자 입장 정리) |
| `data.js` | 논문 표 1(손 젤 원톤)의 호칭별 수치, 기준 금액 5,000원, 설문 결과, 호칭별 인상 순위와 리뷰 수 |
| `messages.js` | 결과에 붙는 문장 |
| `fonts/` | 주아체 글꼴과 그 라이선스 |
| `assets/` | 배경, 캐릭터, 마우스 커서, 누워 있는 공룡 그림, 직업·서비스 선택 그림, 뒤로 가기 숲 그림, 계산하는 사람(`assets/icons/`) |
| `CREDITS.md` | 글꼴과 이미지의 출처와 사용 허가 근거 |
| `vercel.json` | 공개 URL로 올릴 때 쓰는 보안 헤더 설정 |

## 논문 결과를 쓰는 방법

| 논문의 결과 | 앱에서 쓰는 곳 |
|---|---|
| 표 1: 호칭별 곳수·중앙값·가운데 절반·최저·최고(손 젤 원톤) | 가게 한 곳의 가격이 같은 호칭 가게들 사이에서 어디쯤인지, 중앙값보다 얼마나 높거나 낮은지 |
| 기준 금액 5,000원과 설문 30명의 답(5,000원 18명, 10,000원 12명) | 두 가게의 가격 차이를 견줌. 응답자 중 몇 명이 그 정도 차이를 "확실히 다르다"고 답했는지 |
| 호칭 유형 사이 가격 차이가 뚜렷하지 않음(중앙값 차이 최대 5,000원, p=0.146, 지점 표기 가게를 빼거나 리뷰 수가 적은 가게만 보면 차이 0원) | 결과 화면의 이유 칸에 항상 표시 |
| 설문 평소 가격(중앙값 35,000원, 28,000~50,000원) | 가격 칸의 + 버튼의 시작값 |
| 설문 호칭 인상 순서와 이유 경향, 인상 순서와 가격 순서의 약한 관계(0.34) | 결과 화면의 "알아 둘 점", 소비자 입장 정리 |
| 호칭별 리뷰 수 중앙값(인기) | "더 확인해 볼 점" |

- 비교할 수 있는 호칭은 논문에서 5곳 이상이었던 원장, 디자이너, 아티스트, 네일리스트, 선생님입니다. 시술은 논문의 기준 메뉴인 손 젤 원톤 하나만 다룹니다.
- 결과 화면의 "소비자 입장에서 따져 볼 점"은 소비를 받아들일 이유, 소비를 망설일 이유, 더 확인해 볼 점으로 나눕니다. 논문의 숫자로 말할 수 있는 것만 쓰고, 가게를 가라거나 말라고 권하지 않습니다.
- 입력한 가격이 논문에서 본 그 호칭 가게들의 가격 범위(최저~최고) 밖이면 앱은 판단하지 않고 "논문으로는 판단할 수 없어요", "알 수 없어요"라고 알려 줍니다. 위치 판정, 유머 한 줄, 소비를 받아들이거나 망설일 이유를 만들지 않습니다.
- 가게 한 곳일 때 중앙값과의 차이를 5,000원에 견주는 문장은 논문이 두 가격의 차이를 물은 기준을 중앙값과의 거리에 적용한 참고이고, 화면에도 "(참고용)"이라고 적혀 있습니다.
- 두 가게를 넣었을 때 결과 맨 위 한 문장은 금액 없이 "작아요 / 적당해요 / 커요"로만 말합니다(기준 5,000원보다 작으면 작다, 정확히 같으면 적당하다, 크면 크다). 기준 금액은 아래 "이렇게 나온 이유"에 있습니다.
- 논문은 호칭 유형에 따라 가격이 다르다는 뚜렷한 증거는 확인되지 않았다고 정리했고, 인과는 말하지 않았으며, 호칭과 가격이 무관하다고 증명한 것도 아닙니다. 이 앱도 호칭이 가격을 정한다고도, 정하지 않는다고도 말하지 않습니다.

## 데이터

논문의 요약 수치만 들어 있습니다. 표 1(손 젤 원톤 호칭별 곳수·중앙값·가운데 절반·최저·최고), 기준 금액 5,000원, 설문 30명의 요약 결과(확실히 다르다고 느끼는 차이, 평소 가격, 호칭 인상 평균 순위, 일치도와 상관), 호칭별 리뷰 수 중앙값(표 4)입니다. 가게 이름, 시술자 이름, 설문 응답자별 답 같은 개인정보나 가게 단위 원자료는 없습니다. 입력한 값은 브라우저 밖으로 나가지 않습니다.

## 만든 방법 (개발 메모)

- 화면은 직업 선택 → 서비스 선택 → 호칭·가격 입력 → 결과 화면 네 개이고, 모두 `index.html` 한 장 안에서 바뀝니다. 스크립트는 `data.js`, `messages.js`, `logic.js`, `script.js` 순서로 읽고 `globalThis.App` 하나를 공유합니다.
- 판단 규칙: 두 가게는 가격 차이를 기준 5,000원과 견줘 작다(미만)·적당하다(같음)·크다(초과)로 나눕니다. 한 곳은 그 호칭 가게들의 가격 범위에서 낮은 쪽·가운데·높은 쪽 중 어디인지 보고, 범위 밖이면 판단하지 않습니다.
- 결과 문장은 상태마다 한 줄이고 같은 입력이면 같은 문장입니다. 인과를 단정하거나 가게를 가라·말라고 권하는 표현은 테스트(`tests/logic.test.js`, 저장소에 있음)가 막습니다.
- 그림은 `tools/make_pixel_icons.py`(저장소에 있음)가 글자 지도로 그려 PNG로 만듭니다. 고치려면 그 스크립트를 고치고 `python tools/make_pixel_icons.py`를 다시 실행합니다.
- 배포 보안 헤더(`vercel.json`)가 `img-src 'self'`라서 화면 파일에 `data:` 이미지 주소나 인라인 `style` 속성을 쓰면 배포했을 때 막힙니다. 그림은 파일로 둡니다.
